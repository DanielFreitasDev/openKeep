# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

OpenKeep is a self-hostable Google Keep clone. pnpm + Turborepo monorepo, Node 24, strict TypeScript:

- `apps/web` — React 19 SPA (Vite, TanStack Router file-based routes + Query, Zustand, Tailwind 4, TipTap, i18next, PWA)
- `apps/server` — Fastify 5 API + WebSocket + pg-boss jobs; Drizzle ORM on PostgreSQL 18; Better Auth
- `packages/mcp` — MCP server (59 tools); an in-process client of the server's own REST API via `app.inject` — tools must never touch the DB directly
- `packages/shared` — zod schemas, API types, constants; ships TS source, no build step
- `e2e` — Playwright suite

## Commands

- `pnpm dev` — starts dev Postgres via Docker (host port **55432**), then web (:5173) + server (:3000); Vite proxies `/api`
- `pnpm check` — Biome + typecheck for all workspaces; `pnpm lint:fix` auto-fixes style
- `pnpm test` — unit + integration; integration tests need a running Docker daemon (throwaway Testcontainers Postgres), not the dev DB
- Single test: `pnpm --filter @openkeep/server test -- <pattern>` (same form for web/mcp/shared)
- `pnpm test:e2e` — Playwright; needs dev DB up + migrated and chromium installed (`pnpm --filter @openkeep/e2e exec playwright install chromium`); **writes to the dev database**
- `pnpm db:migrate` / `pnpm db:seed` / `pnpm db:up`

## Non-obvious rules (CI enforces these)

- **Changed a route or its schema → regenerate the committed OpenAPI spec**: `UPDATE_OPENAPI=1 pnpm --filter @openkeep/server test -- openapi`. CI fails on `docs/openapi.json` drift.
- **Every EN i18n string needs its pt-BR twin** in `apps/web/src/i18n/locales/` — a parity test fails otherwise. EN strings mirror Google Keep wording verbatim.
- `console.log` is a Biome error (only `error`/`warn`/`info` allowed); server code logs via pino.
- Relative imports in `server`/`mcp`/`shared`/`e2e` need the `.js` extension (nodenext); web does not (bundler resolution). `verbatimModuleSyntax` is on — use `import type`.
- Never hand-edit `apps/web/src/routeTree.gen.ts` (generated by the router Vite plugin).
- DB schema changes: edit `apps/server/src/db/schema/*.ts` → `pnpm --filter @openkeep/server db:generate` → review the SQL in `apps/server/drizzle/` → `pnpm db:migrate`. Migrations also run automatically at server boot.
- New dependency with a postinstall script → allowlist it in `allowBuilds` in `pnpm-workspace.yaml` (blocked by default).
- No CORS anywhere, by design (same-origin SPA + API); do not add it.
- All note access goes through `assertNoteAccess` and the `note_members` row — the single authz + per-user display-state chokepoint.

## Style

Biome only (no ESLint/Prettier): single quotes, 2-space indent, line width 100, trailing commas. Run `pnpm lint:fix` rather than formatting manually.

## Workflow

- Commit directly to `main`. Small, atomic commits in `type: subject` style (`feat:`, `fix:`, `chore:`).
- **Commit types drive releases** (semantic-release, on every push to `main`): `feat:` → minor, `fix:`/`perf:` → patch, `BREAKING CHANGE:` in the footer or `type!:` → major; anything else (`chore:`, `ci:`, `docs:`, `refactor:`, `test:`) ships without a release.
- **Never bump versions or edit `CHANGELOG.md` by hand** — `scripts/set-version.mjs` writes the 7 `package.json` files and `APP_VERSION` during the release, and the release commit refreshes `docs/openapi.json` with it.
- Before considering a change done: `pnpm check && pnpm test`; also `pnpm test:e2e` when the web app changed.
- `docs/PARITY.md` lists known v1.0 deferrals — check it before "fixing" a perceived feature gap. Architecture rationale lives in `docs/ARCHITECTURE.md` and `docs/DECISIONS.md`; MCP usage in `docs/MCP.md`.
